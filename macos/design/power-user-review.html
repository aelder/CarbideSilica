Power User Review

What a person can do quickly in the VerusCarbide terminal interface, and how quickly the same person can do it in Carbide Silica today. Three reviews read the source of the two programs. The claims that the recommendation rests on were checked again in the code.

The short answer: the app has all but three of the functions, and it shows the results better. But a terminal user who sits down at the app loses the thing that made the terminal fast. In the terminal, each deep function is one key from the object, each list moves with j and k, and Esc goes back. In the app, most deep functions need the mouse and a scroll down a long page.

What makes the terminal fast

  • One key for each place. d, m, o, c, F9, F6, the backtick and F2. No key needs a modifier.
  • One key from an object to its deep function. F8 follows a transfer, F4 finds signers, F7 shows branches, n opens notarizations, g asks for a past state, v asks for the historical window.
  • One way to move. j and k select, Enter opens, in each list and on each object. The cursor is there when the screen opens.
  • Esc always goes out. It closes the panel, stops the lookup, or goes back one level. It never quits.
  • Stepping is in place. n and p go to the next and previous block or version, and Back still goes to the screen before.
  • Nothing is below the screen. A deep function opens as a panel on top of the object. The user does not scroll to find it.
  • Raw data is one key away. Tab shows the JSON of the object, y copies the value under the cursor, s saves the file with the name of the object.
  • A different chain is not a different session. Enter on a link to vDEX opens the object on vDEX, and Esc comes back.

What the app does better, and must keep

  • The pictures: the statement by party, the trace as receipt boxes, the identity lanes, the basket in one unit, the state and graph of notarizations, the mempool record, the peer map.
  • Forward, the Recent list, the breadcrumb, and "spent by" on each output.
  • All five charts at one time, with the terminal's keys.
  • Add Node in one command, and the notarization bookmark in one click.

Recommendation

Give the app the terminal's keyboard, not the terminal's screens. Each change below adds a fast way and removes none of the pictures.

  1. Esc goes back. On a page with no field in use, Esc is Back. In a sheet or a field it does what it does now.
  2. One cursor on each page. When a page opens, the keys are live. j/k and the arrow keys move a cursor through the rows and the links of the page: the transactions of a block, the inputs and outputs of a transaction, the rows of each list. Return opens the thing under the cursor. No click is necessary first.
  3. The terminal's letters, when no field is in use. d m o c for places, / for search, n and p to step, b for the block, a for the active block, g for a past state or a seek, v for the historical window, r to read again, y to copy, s to save. The function keys F1 to F10 do what they do in the terminal. The ⌘ keys stay.
  4. Deep functions act on the cursor. Follow Transfer and Witnesses start on the output under the cursor, not on the first one. Each command goes to its card and shows the result.
  5. Stepping is in place. Next and previous block replace the open block. The same keys step through the transactions of a block and the rows of the notarizations.
  6. A command list on ⌘K. Each command of the app and each card of the open page, with its key next to it: "Outputs", "Raw JSON", "State at a chosen block", "Notarizations", "Ban this peer". Type some letters, Return. This removes the scroll, and it teaches the keys.
  7. Raw JSON is a mode. Tab changes the page between the overview and its JSON. In the JSON, the cursor moves through rows, y copies the value, Return follows an ID, s saves with the name of the object.
  8. Copy from the keyboard. ⌘C copies the main value of the row under the cursor. Each link has a copy command. The byte view copies its hex.
  9. Manage from the keyboard. In the peer list: x disconnects, b bans. In bookmarks: e edits, x removes, n adds. In sources: e, m and s as in the terminal, and Return makes the chain current. A chain switch is also in the command list.
  10. Repair what is broken. ⌘R reads each page again. Search keeps a history on the Up key and has a Cancel. The save name has the object in it. The shortcuts window says what is true, and Show Dates gets a key that the system does not use.
  11. Open an object of a different chain in place. This is the only item that needs new work in the bridge, and it needs its own study: the terminal keeps one session for each chain, and the app has one.

What the app must not copy

  • Panels on top of the object. The terminal uses them because it has one screen of text. The app's cards on one page are better to read. The command list and the cursor give the same speed.
  • A key that changes its function. In the terminal, c opens the currency list, or the currency of an identity, or the identity of a currency. In the app, c is the list, and the link has its own stop for the cursor.
  • A search field with no cursor and no history.
  • No way forward.

A possible order of work

  1. The keyboard core. Items 1 to 5 and the ⌘R repair. After this, the loop "open, look, follow, back" needs no mouse.
  2. Reach and raw data. Items 6 to 8 and the other repairs.
  3. Manage. Item 9.
  4. Other chains in place. Item 11, after a study.

Limits of this review

  • The reviews read the source. No person was timed, and the counts of keys are from the code.
  • Five claims about the app were checked a second time in the code: Esc, the focus of lists, the block step, the first-output rule, and ⌘R. The other rows are from one reading.
  • Three points were not tested in the running app: the ⌥⌘D key against the system, ⌘C on a selected row, and the system's Back button in the toolbar.
  • The terminal's keys inside the chart, witness and bookmark panels are from its reference document and its source, not from a run of the terminal.
  • The terminal cannot add a public API or set a ban time. The app cannot do these also. They are not in the list.
