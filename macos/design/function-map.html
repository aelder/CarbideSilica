Carbide Function Map

Everything Carbide's terminal app does, sorted by what the person is trying to accomplish and how hard it is today. This is the list the Mac app has to cover, and the order to cover it in.

Sources: Carbide's README and explorer reference, plus a sweep of the source for features the docs leave out. Several functions here are not documented upstream, including identity origin, tokenized control, registration payments and value accounting.

The six objects, and how you move between them

Almost every function is a view of one of six objects or a walk along one of these links. Carbide's keys (b, c, n, F3, F8) are shortcuts for specific arrows. In the Mac app each arrow becomes a visible, clickable link.

The seven hard tasks

The most demanding things people do with Carbide, restated as the question the person actually has. They are where the terminal asks the most of its user, so they are where a GUI can help the most.

1

Where did this transfer or conversion end up?

Today
Open the transaction, select the right output, press F8, then read a hop list. For a cross-chain transfer you search the destination chain yourself in 1,000-block windows with g, [ ] and s. Up to eight legs, each with its own evidence.
In Silica
A route drawn left to right: Sent → Exported → Imported → Received. Each leg is a card with the amount, the rate it converted at and the fees. The destination search runs on its own with visible progress. One verdict at the top: Received, Refunded, Forwarded or Still unresolved.
2

What is this transaction actually doing?

Today
Read up to a dozen header lines, a row of tags, then input and output tiles. Fee and value lines carry qualifiers such as "partly derived", "known + hidden" and "unknown (protocol accounting)".
In Silica
One plain sentence first, built from the tags: "Converted 100 VRSC to DAI through Bridge.vETH." Below it, a money-flow picture from inputs to outputs with the fee shown as its own slice. Hidden amounts are drawn as hidden, never as zero.
3

Who controls this identity, and where did it come from?

Today
Spread across four places: authority fields, the tokenized-control check (Enter, 16 hops per pass), the registration and associations panel (funding candidates, referral chain) and a historical reverse lookup (v, one 1,000-block window at a time).
In Silica
A Control card answering three questions in words: who can spend, who can revoke, who can recover, plus the current token holder if control is tokenized. An Origin timeline: name commitment → registration → each update, with who paid and who referred.
4

Are these two chains agreeing with each other?

Today
From a currency press n for the notarization browser, Tab to swap perspective, [ ] to pick a proof root, then F4 in the transaction to see who signed. Signature groups are explicitly not a quorum count.
In Silica
Two parallel chain lanes with each notarization drawn as a tie between them. A tick where the committed block is on the active chain, a warning where it is off-chain or missing, and a grey mark where the other chain's source isn't connected. Signers listed beside each tie.
5

What did this currency look like on a given date?

Today
g to seek by height or date, a to check activity at that height, w for the preceding 1,000 blocks, [ ] for adjacent windows.
In Silica
A date scrubber above the currency page. Supply, reserves and prices redraw for the chosen moment, with imports and exports listed underneath for that period. "Now" is one click back.
6

Was this block or transaction ever on a different branch?

Today
F7 lists stored inclusions and child branches, 100 per page, with active, orphaned and unverified labels kept per source.
In Silica
A small branch diagram at the affected height: the active path and each orphaned sibling, with which source saw which. Shown only when more than one branch is known, so the common case stays quiet.
7

What else does this output refer to?

Today
F3 in a transaction lists notarization, evidence, finalization and import/export references, each with one of nine resolution statuses.
In Silica
References appear inline on the output they belong to, as links that name the other end: "Finalizes export in transaction …". The nine statuses reduce to the four confidence levels below.

How the app is organised

Three kinds of place. The sidebar holds what you go to. Object pages hold what you look at. Search is always in the toolbar, because it is the fastest way to anything.

Watch

Sidebar · live, no input needed
  • Dashboard chain health, recent blocks and transactions
  • Mempool what is waiting to confirm
  • Charts five metrics, with the estimator

Explore

Sidebar · browse and filter
  • Currencies pools, tokens, chains, gateways
  • Marketplace open offers
  • Notarizations chain-to-chain agreement

Library

Sidebar · yours
  • Bookmarks saved places with notes
  • Recent the trail you have walked

Node

Sidebar · the machine, not the chain
  • Sources daemons, APIs, which chain
  • Peers list, map, actions
  • Storage cache size and reset

Every object page has the same five tabs

SummaryThe plain sentence, the key numbers, the status.
ActivityWhat it did or what happened to it.
HistoryEarlier versions, earlier states, other branches.
EvidenceTraces, references, signers: the investigations.
JSONThe daemon's own data, untouched.

The investigations are not sidebar destinations. They start from the object they are about, which is how the question arises: you are looking at a transfer and want to know where it went.

Rules for showing the data

Carbide is precise, and it shows that precision as text. The app's job is to keep the precision and remove the reading.

Say what it is first

Every page opens with one sentence a person could say out loud. Fields come after.

Tags: Reserve Transfer, Conversion, Export → "Sent 100 VRSC to be converted to DAI on vETH"

Names before addresses

Show the identity or currency name; keep the i-address one hover or one copy away. Carbide makes this a toggle. In the app it is the default.

i9nwxtKuVYX4MSbeULLiK2ttVi6rUEhh4X → vETH

Time before height

Lead with the date and how long ago. Height is the secondary label. Future heights say "est." as Carbide does.

4,226,272 → 6 Sep 2026, 13:19 · block 4,226,272

Amounts always carry a ticker

No satoshis, no bare numbers. A hidden shielded amount is drawn as hidden. An unknown fee says unknown and why.

300046564 → 3.00046564 VRSC

Shape, colour and word together

Status never depends on colour alone. Mined and staked, confirmed and pending, launched and failed each get a distinct mark and a word.

Three depths, never more

Glance (the sentence and status), detail (the fields), evidence (how we know). A person stops at the depth they need.

Keep the non-claims

Carbide is careful to say what it has not proven. Those sentences stay, in plain words, wherever a result is partial.

"Not found in the blocks searched. That does not mean it doesn't exist."

Raw data one click away

The JSON tab is on every page. Nothing the app simplifies is ever unavailable in its original form.

Four confidence levels replace dozens of labels

Carbide marks uncertainty with dozens of phrases: retained observation, membership unverified, funding candidate, receipt unresolved, partly derived. They are all accurate, and they fall into four kinds. One consistent mark for each makes trust readable at a glance.

VerifiedProven by exact match or replay.Received verified · Supply burn verified · Both sides resolved
ObservedA source reported it, at a known block. Not re-checked since.Retained observation · Last observed active · Membership unverified
CandidateA reasoned guess, shown as a guess.Funding candidate · Destination-address candidate · Partly derived
UnknownA gap, with the reason it is a gap.Receipt unresolved · Counterpart not loaded · Spender unresolved

Suggested build order

Ordered so that each step makes the next one cheaper, and the hard tasks land on pages that already read well.

  1. The presentation layer. Names, dates, tickers, status marks and the four confidence levels, applied to the five pages that already exist. Everything later inherits it.
  2. Finish the object pages. The plain-sentence summary, transaction money flow and value accounting, identity versions, address activity, currency option badges.
  3. The sidebar and the Watch group. Mempool, recent transactions on the dashboard, bookmarks and the recent trail.
  4. Explore. Currency browser with filters, marketplace.
  5. Charts and the estimator.
  6. The hard tasks, in the ranked order above, starting with following a transfer.
  7. Node. Multiple sources and chains, peers and map, storage. Carbide's SQLite cache comes in here, since history, reorgs and offline use depend on it.
