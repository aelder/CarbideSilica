Carbide Silica · design study

Silica Visual Methods

A terminal can only arrange characters in a grid. A window can use position, size, connection and motion to carry meaning. These are thirteen working studies of where that difference changes what a person understands, and how fast.

Every picture below runs on simulated data shaped like real Verus data. In the app the same views would be fed by the daemon through Carbide's existing code.

What a window can say that a grid of text can't

Position can be time

Put events where they happened on a time axis and rhythm, gaps and bursts become visible without reading a single timestamp.

Size can be amount

Draw a value as a width and the eye compares it before the mind reads the digits. A fee that is a hair beside a payment needs no explanation.

A line can be a relationship

"A funds B", "X can revoke Y", "this export became that import". Text states these one per row. A line shows them all at once.

Motion can be change

A mark that appears, moves or fills is noticed without being looked for. Refreshing a table makes you find the difference yourself.

The hand can ask the question

Dragging a date, hovering a mark, brushing a range: the question and the answer happen in the same place, with no command to remember.

Overview and detail can coexist

A terminal shows one or the other. A window keeps the whole picture in view while one part of it is opened up.

Three tests that keep this from being a skin

  1. It answers a question the terminal needs several screens for. If the picture only restyles one table, it stays a table.
  2. Every mark is the real object. Clicking a block mark, a flow band or a node opens exactly what Carbide would open, with the same data and the same caveats.
  3. Nothing is rounded away. Exact figures, raw JSON and Carbide's uncertainty labels are one step from every picture, and each picture has a table form for people who prefer it.

What carries over from Carbide unchanged

    
    
      
  1. The engine. Every picture is a different rendering of data Carbide's code already fetches and verifies. No analysis is reimplemented.
    2. 
      
  2. The honesty. Verified, observed, candidate and unknown keep distinct marks in every view: solid, half, dashed and dotted.
    3. 
      
  3. The keyboard. Search, back, next and previous, and the investigation shortcuts keep working for people who know them.
    4. 
      
  4. The text. Each view has a table form and a JSON tab. Pictures are the default, never the only way in.
